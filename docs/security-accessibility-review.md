# Security and accessibility review

Date: 2026-11-26 · Scope: `apps/api`, `apps/mobile`, `packages/*` at the head of `feat/security-a11y`. Method: line-by-line reading of every API route, auth and config module, the mobile session and storage code, plus automated checks (axe-core WCAG 2.1 A/AA on every screen of the web build, `npm audit`). No external penetration test was done.

## Reviewed and in good shape

- Passwords: argon2id (OWASP parameters), timing equalised for unknown emails, 10+ characters with letters and digits.
- Sessions: 15-minute HS256 access tokens with issuer, audience and algorithm pinned; 30-day opaque refresh tokens stored only as SHA-256 hashes, rotated on use, reuse revokes the whole family; deactivated or deleted accounts are rejected on every request.
- Authorisation: every user resource is scoped by `user_id` in SQL; other users' assessments and exports return 404 (existence not revealed). Covered by tests.
- Input validation: zod schemas on every body and parameter; database CHECK constraints mirror the measurement rules (no SpO₂ or BP values, units match metrics, demo data must be simulated).
- Errors: one envelope with a request id; unexpected errors never return internals.
- Logging: authorization headers, cookies and bodies are redacted; audit events carry no health data.
- Headers: helmet defaults (HSTS, nosniff, frame denial); body limit 256 KB; global rate limit 300/min per IP, auth routes 10/min.
- Mobile storage: tokens in the iOS Keychain / Android Keystore via expo-secure-store. Camera frames never leave the device.
